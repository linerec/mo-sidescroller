# 모찌의 숲 · Blender 모듈 제작과 맵 조립 규약 v1

## 바로 사용하기

`npm run dev` 후 [숲 맵 공방](http://localhost:8080/map-editor.html)을 엽니다. 게임 타이틀에서도 들어갈 수 있습니다. 두 스테이지 모두 이 공방과 같은 JSON·Blender GLB를 사용합니다. 별도로 모델을 가져오는 작업은 필요 없습니다.

1. 스테이지를 고르고 **땅**으로 격자를 드래그합니다. 잔디 윗면·옆 가장자리·매달린 뿌리가 이웃 칸을 보고 붙습니다.
2. **통과 발판**을 길게 그립니다. 왼쪽 끝·중간·오른쪽 끝을 자동 선택하며, 한 칸이면 단독 발판이 됩니다.
3. **Blender 소품**에서 나무·고사리·버섯 등을 고르고 거리와 크기를 선택한 뒤 격자를 클릭합니다. 소품은 클릭한 칸 아래쪽 중앙에 놓입니다. 실제 모델 미리보기의 **선택한 칸 보기**로 확인하세요.
4. **모찌 시작점**을 안전한 땅 위에 찍습니다. 시작점은 플레이어 물리 중심입니다. 땅이 있는 칸의 바로 위 빈 칸에 찍으면 바닥으로 내려앉습니다.
5. **초안으로 플레이**를 누릅니다. 브라우저에 초안을 저장하고 새 탭에서 그 맵을 실행합니다. 시작 대화를 생략하며, 테스트 중 게임 진행은 정식 세이브에 기록하지 않습니다.
6. 확정하려면 **맵 JSON 내보내기**로 받은 파일을 프로젝트의 `maps/stage-1-1.json` 또는 `maps/stage-1-2.json`에 반영합니다. 일반 게임을 새로 열면 적용됩니다.

격자는 가로·세로 스크롤할 수 있습니다. 지우개는 해당 칸의 지형과 수동 장식을 함께 지웁니다. 되돌리기/다시는 최근 50회 작업을 지원합니다. 스테이지를 바꾸어도 현재 탭의 작업은 유지됩니다. 탭을 닫기 전에는 **브라우저에 초안 저장** 또는 JSON 내보내기를 사용하세요. 초안은 같은 주소·포트·브라우저의 localStorage에만 보관됩니다. `localhost`와 `127.0.0.1`은 서로 다른 저장 공간입니다.

## 1m 격자와 좌표

Blender에서는 **+Z가 위, -Y가 정면**입니다. glTF Y Up으로 내보내면 게임에서는 **+Y가 위, +Z가 카메라 쪽**입니다. Blender 1 unit = 게임 1m = 격자 1칸입니다. 물리는 XY 평면에서 동작합니다.

| 종류 | 원점 | 규격 / 위치 |
|---|---|---|
| `soil_a/b` | 칸 좌하단 | 게임 X 0~1, Y 0~1, 깊이 2m. 연결면은 정확히 평면 |
| `top_a/b` | 지표면 왼쪽 | 흙 칸 `(x,y)`의 `(x,y+1)`에 붙임. 이끼 띠는 표면 아래에 있고 풀만 위로 나옴 |
| `edge_left/right` | 칸 좌하단 | 해당 칸의 왼쪽/오른쪽에 이끼와 잔뿌리 |
| `roots` | 노출된 밑면 왼쪽 | 공중 흙 덩어리 밑으로 늘어지는 장식 |
| `platform_*` | 걸을 면 왼쪽 | 폭 1m, 두께 0.3m. 본체 Y -0.3~0 |
| 나무·소품 | 바닥 중앙 | 크기는 종류별로 다름. `footprint`는 조경 참고값이며 충돌 크기가 아님 |

Blender 원본에서 모듈의 Empty를 기준으로 자식 메시 위치·회전·스케일을 적용해 둡니다. 게임에서 루트를 원점에 놓았을 때 위 표의 좌표가 나와야 합니다. 흙 연결면에는 베벨을 주지 않습니다. 눈에 보이는 앞면과 잔디 장식으로만 둥근 느낌을 더해, 여러 칸을 붙여도 구멍이 생기지 않게 합니다.

## 조각 선택과 충돌

지형 JSON의 `rows`는 화면 위부터 아래 순서입니다. 맨 아랫줄은 게임 Y=0~1입니다.

| 문자 | 게임 동작 | 시각적 조립 |
|---|---|---|
| `.` | 빈 공간 | 지형 조각 없음 |
| `#` | 고정 충돌 지형 | 흙 + 노출된 윗면/좌우면 + 일부 노출 밑면 뿌리 |
| `=` | 아래에서 통과, 위에서 착지 | 좌우 `=` 이웃에 따라 단독/왼쪽/중간/오른쪽 발판 |

같은 줄의 인접 `#`는 기존 `buildFromAscii`가 긴 충돌 박스로 합칩니다. 그림은 1m 모듈로 조립합니다. 좌우 연결 판정은 충돌을 만드는 JSON에서 직접 계산하므로 공방과 게임이 같은 결과를 냅니다. 흙 A/B 변형은 좌표와 `seed`로 고정 선택합니다. 장식을 지워도 다른 칸의 무늬가 갑자기 바뀌지 않습니다.

기존 엔진의 `=`는 칸의 Y+0.5를 중심으로 하는 높이 0.3의 콜라이더입니다. 따라서 **실제 착지면은 Y+0.65**이며, GLB의 표면 원점도 여기에 맞춥니다. 공방 격자에서도 이 높이에 선을 그립니다. 이동 발판은 정수 너비만 사용하고 `dressMovingPlatform`으로 같은 조각을 붙입니다. 높이가 0.3과 다르면 외형 두께만 맞추며 윗면은 콜라이더에 고정합니다.

나무·꽃·바위·돌문 등 조경 소품은 충돌이 없습니다. 돌문은 현재 배경 랜드마크입니다. 들어갈 수 있는 출구나 퍼즐 문은 `ExitDoor`/`Gate`로 별도로 만듭니다. 식물의 잎과 뿌리 때문에 보이지 않는 벽이 생기지 않습니다.

## 모듈 목록과 미술 규칙

24종: 흙 2, 잔디 윗면 2, 좌우 가장자리 2, 뿌리 1, 발판 4, 나무 3, 관목 2, 고사리·버섯·꽃·풀·바위·돌문·먼 나무·언덕 각 1입니다.

큰 둥근 수관, 굽은 나무줄기, 크림색·연두·이끼·산호색의 무광 재질로 동화의 작은 무대처럼 만듭니다. 가까운 식물은 색을 선명하게, 먼 나무와 언덕은 안개색으로 낮춥니다. 캐릭터 얼굴과 발판의 착지선 주변은 작고 낮은 식물로 정리합니다. 큰 나무는 게임 Z=-12 부근 또는 그 뒤에 놓으세요.

수동 장식 거리 프리셋은 `near=-3`, `mid=-12`, `far=-32`입니다. 원근 카메라로 스크롤할 때 자연스러운 시차가 납니다. 자동 숲은 같은 seed에서 같은 나무·관목 배치를 만듭니다. **먼 숲 자동 배치**를 끄면 자동 조경이 사라지고 수동 배치로 구성할 수 있습니다. 지표면의 작은 꽃·버섯은 노출된 지형에 계속 자동으로 붙습니다.

현재 나무 메시 자체에는 바람 애니메이션이 없습니다. 움직임은 나비·꽃가루·빛·물에 들어 있습니다. `glade`의 장식 물줄기는 현재 1–2의 X=11에 맞춰져 있습니다. 다른 맵에 물을 옮기려면 `ForestAtmosphere.js`의 배치 좌표를 수정하세요. 물은 배경 효과이며 낙사 구간의 충돌을 채우지 않습니다.

## JSON과 새 스테이지

```json
{
  "version": 1,
  "id": "stage-1-1",
  "mood": "morning",
  "seed": 71,
  "spawn": { "x": 3, "y": 3 },
  "autoForest": true,
  "rows": ["........", "........", "########", "########"],
  "decorations": [
    { "asset": "tree_willow", "x": 5.5, "y": 2, "layer": "mid", "scale": 1.5 }
  ]
}
```

폭 8~160, 높이 4~64, 수동 장식 최대 300개, 배율 0.25~3을 검증합니다. 격자 크기를 줄일 때는 우측/상단이 잘리고 좌하단은 유지됩니다. 잘못된 JSON은 불러오기를 거부하고 현재 작업을 유지합니다.

현재 공방은 등록된 두 스테이지의 **지형·시작점·조경**을 편집합니다. NPC·적·아이템·레버·문·이동 발판·대화 트리거는 `src/stages/ch1/*.js`에서 관리합니다. 공방의 회색 표시는 주요 이야기 오브젝트 참고 위치입니다. 그 아래 땅을 옮기면 스테이지 코드의 좌표·순찰 범위·체크포인트·점프 경로도 확인하세요. 맵을 줄인다고 출구나 퍼즐이 자동 이동하지 않습니다.

새 스테이지는 `MapData.js`의 `MAP_IDS`, 공방 스테이지 선택지와 참고 마커, `maps` JSON, 스테이지 레지스트리와 챕터 순서에 추가합니다. 아래 순서로 생성합니다.

```js
const map = await loadMap(this.id);
this.game.applyEnvironment(FOREST_ENV[map.mood]);
this.setBounds({ minX: 0, maxX: map.rows[0].length, minY: -1, maxY: map.rows.length + 4 });
buildFromAscii(this, map.rows.join('\n'), { tile: 1, visual: false });
this.spawnPlayer(map.spawn.x, map.spawn.y);
await mountWoodland(this, map);
// NPC, 문, 적 등은 이 뒤에 추가
```

`onUpdate`에서는 `this.forest.update(this.time)`를 호출합니다. 가져올 경로는 기존 두 스테이지를 참고하세요.

## Blender에서 수정하고 다시 내보내기

원본을 열고 `ENV_<asset_id>` 아래의 메시를 수정합니다. 기본 모듈은 하나의 메시 안에 재질 슬롯을 유지하므로 편집 모드에서 연결된 부분 선택으로 수관·가지 등을 고칠 수 있습니다. 새 모듈에는 루트 Empty의 `asset_id`, `kit_version=1`, `anchor`, `role`, `footprint` 커스텀 속성을 넣고 manifest에도 같은 ID를 등록합니다.

게임 라이브러리에 포함할 Empty와 메시만 선택해 GLB로 내보냅니다. **Selected Objects, Active Scene, Y Up, Custom Properties**를 사용하고 카메라·조명·스튜디오 바닥·이름표는 제외합니다. 캐릭터와 달리 이 환경 라이브러리는 애니메이션을 내보내지 않습니다. 새 수동 소품 ID는 `MapData.js`의 `PROP_IDS`에도 추가하면 manifest의 한국어 이름으로 공방 선택지에 나타납니다. 새 지형 규칙은 `tilePlacements`와 충돌 빌더를 함께 수정해야 합니다.

Blender MCP로 전체 초기 키트를 다시 생성하려면:

```python
MO_PROJECT_ROOT = '/absolute/path/to/Mo'
path = MO_PROJECT_ROOT + '/tools/blender/build_forest_kit.py'
exec(compile(open(path).read(), path, 'exec'))
bpy.ops.render.render(write_still=True)
```

이 스크립트는 별도 씬에서 작업하며 열려 있는 다른 작업 파일을 덮어쓰지 않습니다. 같은 경로의 숲 산출물은 갱신합니다. 원본에서 수작업으로 고친 내용은 생성 소스에도 옮기거나 별도로 보관한 뒤 실행하세요. `.blend`는 해당 씬만 독립 저장합니다.

## 성능과 검증

GLB의 메시·재질은 한 번 불러와 공유합니다. 반복 배치는 `InstancedMesh`로 묶고, 스테이지 전환과 공방 재조립 때 인스턴스 버퍼 및 거리색 재질만 해제합니다. 원본 기하/재질은 앱 수명 동안 캐시합니다. 복잡한 모델을 많이 배치하면 인스턴싱을 해도 삼각형 처리 비용은 늘어나므로 모듈 밀도와 메시 크기를 함께 관리하세요.

- `npm run check:world`: GLB 24종·원점/경계·콜라이더 메타데이터, 자동 연결, JSON 검증.
- `tools/check-forest-browser.cjs`: 실제 두 스테이지 GLB 로딩, 열린 낭떠러지, 성능 예산, 재진입 리소스, 일시정지, 모바일.
- `tools/check-map-editor-browser.cjs`: 칠하기·되돌리기·소품·맵 전환·저장/내보내기·잘못된 JSON·초안의 실제 게임 충돌·세이브 보호.

브라우저 검사는 실행 중인 로컬 서버와 Playwright가 필요합니다. 기존 설치는 `PLAYWRIGHT_PACKAGE=/path/to/playwright`로 지정할 수 있습니다. 현재 충돌은 직사각형과 통과 발판입니다. 경사면·물리 기반 줄다리·절차적 던전·이야기 오브젝트의 시각 편집은 이 공방에 포함되지 않습니다.
